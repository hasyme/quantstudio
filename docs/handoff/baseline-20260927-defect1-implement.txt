## 数据修复首轮试跑发现（2026-09-27，daemon 已停）

**结果**：修复代码生效，但 `etf_daily` 任务 FAILED，暴露两个问题：

1. **已修复：DuckDB 连接配置冲突**（审计第四轮②实锤）
   - 现象：`读主库 etf_daily.close 失败: Connection Error: Can't open a connection to same
     database file with a different configuration`
   - 根因：`_get_local_daily_close` 用 `read_only=True`，与 daemon writer 的 read-write 连接冲突
   - 修复：改 `read_only=False`（与 writer 一致；本方法只 SELECT）→ 复测 Connection Error 消失

2. **未决：历史缺日无参考死锁 + 云端复权口径**
   - 159325 @ 2026-09-11：`ratio=1.999`（除权日 09-14），但本地 etf_daily 缺 09-11 →
     无参考 → 选项 A fail-fast → **参考永远写不进（死锁）**
   - 深层：云端 `close` 用最新因子前复权（qfq）、`adj_factor` 用当天因子 → 口径矩阵见
     `docs/evidence/cloud-caliber-matrix-forensics-20260927.md`
