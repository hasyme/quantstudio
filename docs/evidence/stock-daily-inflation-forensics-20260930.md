## 3. 关键矛盾：A′ 口径矩阵与实测冲突

### 3.1 设计文档的认定

`docs/anchor-drift-fix-design-a-prime.md`：
- L31：`stock_daily` 云端 **恒 qfq**（剔 300803 后 100%）
- L57：日线表「在 `_restore_to_raw` 还原层本来就正确（qfq × ratio = raw）✓」

### 3.2 实测反证（688286 @ 2026-01-12）

```
云端 stock_minutes 15:00 close = 59.787   ← 已确证 minutes 云端 = raw
云端 stock_daily       close = 59.787   ← 与 minutes 同值
本地 stock_minutes（本轮写入）  = 59.790   ← 正确（= 云端 raw）
本地 stock_daily              = 83.690   ← 放大 1.40 倍
83.690 / 59.787 = 1.3998 ;  adj_latest/adj_i = 1.3998  ← 精确吻合
```

**推理链**：
1. `stock_minutes` 云端 = raw（口径矩阵已确证，107/107）；
2. 同一 `(code, day)` 的云端 `stock_daily` **与 minutes 同值**；
3. → **该日云端 `stock_daily` 也是 raw**；
4. 但 A′ 认定 `stock_daily` 恒 qfq → 施加 `× adj_latest/adj_i` → **把 raw 放大 1.40 倍**。

### 3.3 另一独立验证（000028）

若云端是 `qfq@adj_i` 基准，则 `raw = cloud × adj_latest/adj_i = 25.11`（= 本地值）；
若云端是 `qfq@adj_latest` 基准，则 `raw = cloud = 22.214`。
**本地 = 25.11 → 与"云端为 qfq@adj_i"自洽**。

→ 两种解释都指向同一结论：**A′ 的 `× adj_latest/adj_i` 在"云端已是 raw"时不成立**，
而实测显示**部分 code/日期云端确实已是 raw**。

## 4. 影响评估

| 面 | 影响 |
|---|---|
| **A3 验收判据** | **失效**——`stock_daily` 是比对基准，基准自身有 16% 偏高 |

| **解释 A2R1 现象** | 重拉把 minutes 修正为正确值，而基准 daily 仍错 → 不一致率**上升**（44.87% vs 52.50%） |
| 与缺陷1 关系 | **独立**：缺陷1 是 minutes 侧；本问题是 daily 侧 |
| 与缺陷2 关系 | **不同列**：缺陷2 是 `close_front` 冻结；本问题是 `close` 放大 |

## 5. 结论

1. **`stock_daily` 存在独立的放大缺陷**，影响约 **16%** 行（最大 1.94 倍）；
2. **放大公式 = A′ 的还原公式** `× adj_latest/adj_i`（精确吻合）；
3. **根因是口径矩阵对 `stock_daily` 的认定与实测冲突**：
   矩阵认定恒 qfq，但至少部分 code/日期云端已是 raw；
4. **该问题使 A3 判据不可用**，须先解决或改用云端直取作基准；
5. **不是 A′ 引入的**（最新写入 09-24 早于 A′ 09-28），但 **A′ 沿用同一公式，
   会在下次写入时继续放大**。
