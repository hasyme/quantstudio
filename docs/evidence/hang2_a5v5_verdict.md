## 关键发现

1. **显式 CHECKPOINT 基本是空操作**：本 run 共调用 8 次，其中至少 3 次明确返回
   `wal=0，无需检查点`（其余为 `ok=True`）⇒ **DuckDB 自动检查点已在批间把 WAL 收敛**，
   显式 `CHECKPOINT` 无 WAL 可刷。
2. **库膨胀不是 WAL 造成的**：本次开启 CHECKPOINT 后 DB 仍由 3.13GB → **3.64GB**（+510MB），
   停点不变 ⇒ F8 膨胀的真正来源是 **upsert 产生的删除版本 / row-group 碎片**，
   而非未收敛的 WAL。DuckDB 1.4 无 `VACUUM`，**只能靠主键重建（V7）回收**。
3. **本轮无部分提交**：V1 关闭 ⇒ 单条 5 万行语句整体回滚，表行数保持
   **2,764,437**（与 A5-1 结束时一致，`max_time=2022-08-15`）⇒ 反向印证 A5-1 的
   +15,000 行确为 V1 的子批部分提交（R-4 预告的代价），且幂等无重复。
