## 2. 重大发现：污染的真实性质（推翻此前理解）

### 2.1 抽样证据（688286 @ 2026-01-12）

| 来源 | 值 |
|---|---|
| 云端 `stock_minutes` 15:00 close | **59.787** |
| 云端 `stock_daily` close | **59.787**（与分钟**完全一致**） |
| 云端 `adj_factor` | 1.003 |
| **本地 `stock_minutes`（本轮写入）** | **59.790** ≈ 云端 ✓ |
| **本地 `stock_daily`** | **83.690** ✗ |

### 2.2 定量吻合

```
本地日线 / 云端 = 83.690 / 59.787 = 1.3998
adj_latest / adj_i = 1.4040 / 1.0030 = 1.3998
```

**精确吻合到 4 位小数。**

### 2.3 结论

1. **云端两表口径一致且正确**（`stock_minutes` 与 `stock_daily` 同值）；
2. **本地 `stock_daily` 被 `adj_latest/adj_i` 放大了 1.4 倍**；
3. 即 **A′ 对 `stock_daily` 无条件施加「qfq→raw」还原公式**，
   而该表的云端值在此场景下**已是 raw 基准**（`is_qfq=True` 但 `adj_i≈1.003`，
   因子接近 1，还原反而引入 1.4 倍误差）；
4. **因此"污染"不是单一的分钟表问题**——`stock_daily` 也有独立的放大问题，
   且**它是我用来做比对基准的表**！

### 2.4 对验收判据的致命影响

A3 主判据 = 「`stock_minutes` vs `stock_daily` 配对一致率」。
但**基准表 `stock_daily` 自身存在放大误差** → 该判据**不可靠**：
- 若 `stock_daily` 偏高 1.4 倍，则配对必然不一致（即使分钟侧正确）；
- 实测"重拉窗口更差"正是此因：分钟侧被修正为云端正确值(59.79)，
  而基准 `stock_daily` 仍是错的(83.69) → 不一致率反而上升。
