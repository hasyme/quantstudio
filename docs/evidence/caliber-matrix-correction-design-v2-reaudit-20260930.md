## 二、本轮新增代码核查：A1/A2 验收的可达性（V1 未覆盖）

V2 的 A1/A2 期望「非成员三表报 `caliber="raw"`/`is_qfq_restored=False`」。这依赖
一个 V1/V2 均未论证的问题：**非成员表是否还能走到 `meta` 生成的代码路径**。核查确认
入口为两层结构：

```
_restore_qfq_if_required
  ├─ L1742 入口白名单：_requires_qfq_restore = (table,freq) ∈ _QFQ_ADJFACTOR_TABLES
  │   （四表 × 频率全集，P1 不改此集合）→ 四张行情表全部放行进入
  └─ _restore_to_raw
       └─ L2072-2075 内部分流：table ∈ _QFQ_CALIBER_TABLES（P1 收缩对象）
           ├─ 成员：ratio = adj_latest/adj_i，meta.caliber="qfq"
           └─ 非成员：ratio = 1.0，meta.caliber="raw"，is_qfq_restored=False
```

**结论：P1 收缩后，stock_daily/etf_daily 与 stock_minutes 走完全同构的非成员路径，
A1/A2 按字面可实现。** 且该路径已被生产验证（stock_minutes 为 A′ 已实施先例，
107/107 + 云端基准 99.9%）。

## 三、新增修订项

### R-1 🔴 必改（文字级，更正后免重审）：开关置位前置条件绑错对象

V2 §3.1② 写「`_CALIBER_BLOCK_STOCK_MINUTES` 在 **P2 重拉**验收通过后置 True」。
**P2 只重拉 stock_daily/etf_daily 两张日线表，而该开关的阻断对象是 `stock_minutes`**
（quality_audit.py L783-784/L1001-1006）。开关设计意图（L992-997、L576-579 注释）是
「**缺陷1 污染数据修复（stock_minutes 全历史重拉）**验收通过后」置 True——届时本地
应为纯 raw，翻转即真回归。V2 自己在 §3.2 也承认「剩余工作：重拉 **minutes 全历史**」
（独立于 P2）。

若按 V2 字面在 P2 验收后置 True，而 minutes 历史污染（膨胀长尾 p99 1.11/max 18.7）
尚未修复，阻断档将在「本地非纯 raw」状态下提前激活——违背开关设计意图；多数票虽
大概率仍判 raw 不误报，但万一探针窗内污染密集致票型误判 qfq，会误阻断。

**溯源（审计方认领）**：此错误源于前轮审计 C-4 建议表述不严谨（「应在 P2 重拉验收
通过后置 True」未区分 P2 与 minutes 全历史重拉两件事），V2 忠实采纳而继承。非方案
作者新引入。

**更正文字（可直接替换 §3.1②）**：

> ② `_CALIBER_BLOCK_STOCK_MINUTES`（`quality_audit.py:580`，现 `False`）→
> 在**缺陷1 stock_minutes 数据修复（minutes 全历史重拉）验收通过后**置 `True`。
> 注意：**≠ 本方案 P2**（P2 仅重拉两张日线表）；minutes 重拉与 P2 均完成前保持
> `False`。

### R-2 非阻断（顺手改）：§7 风险表过时行

「门禁语义调整引入误报｜中」——§3.1 已改为「逻辑零改动」，此行依据失效。
建议改为：「开关置位时机不当引入误报（见 §3.1②/R-1）｜低-中｜绑定 minutes 数据修复
验收节点，勿提前置位」。

### R-3 非阻断（建议性）：A1 增补一条显式锁定断言

核查 `_restore_to_raw` 主体确认：**非成员表仍将经过三处 fail-fast**（缺 adj_factor
列 L1988、缺 code 列 L2005、因子无效 L2052）及 `_sync_factor_snapshot` 失败 raise
（L1755-1758）——即「不还原的表仍要求因子完整，因子缺失照旧 fail-fast」。这与
stock_minutes 现状同构、已被生产验证，**非 P1 引入的新行为**；但建议在 A1 验收中
增补一条单测断言将其显式锁定（「非成员表因子缺失仍 fail-fast」），防止未来被当作
「不还原就不需要因子」误优化掉。

### R-4 未决项闭环（本轮裁定）

§8-1「收缩 vs 删除机制：待审计确认」→ **确认收缩为 `{etf_minutes}`**。
理由：etf_minutes 在用（P5 确认 QFQ）；门禁依赖还原后语义；删除机制 = 死代码化，
违背「保留能力」原则。该未决项可在 V2.1 中直接标记闭环。
