## 1. 背景与目标

A′ 是**表级硬编码**口径方案：

| 表 | A′ 认定云端口径 | A′ 动作 | 期望本地 `close` |
|---|---|---|---|
| `stock_daily` / `etf_daily` / `etf_minutes` | qfq | 还原 raw | **raw** |
| `stock_minutes` | raw | 不还原 | **raw** |

口径漂移 = 静默写错（无异常、无日志），故 §5.3 要求增门禁：
`stock_minutes` 翻转 → **阻断**；其余表翻转 → **告警**。

**未决项**（§7-2/§7-3）：抽样量、阈值、告警通道「实施时定」。本节即该项取证。

## 2. 实现与迭代过程（含两次实质缺陷与修复）

门禁判别模型：除权日 D 处令 `k = adj_D/adj_{D-1}`（取自 `qfq_aux.db` 因子表，
**独立于被测输出**），实测本表 `close` 跨除权日比值 `r = close_D/close_{D-1}`：

- `r ≈ 1`   → 输出 qfq（未还原）
- `r ≈ 1/k` → 输出 raw（A′ 预期态）
- `r ≈ 1/k²`→ 双重复权（云端已 raw 而管线又还原一次）

### 缺陷 ①：分割点误用 `ex_ms - 2d`（已修）

初版以 `ex_ms - 2*86400_000` 切「除权前/后因子」。实测因子步进**恰在除权日**：

```
600812  ex=2026-06-11  step@2026-06-11  4.0577 → 4.0856
600602  ex=2026-07-28  step@2026-07-28  543.9295 → 545.1594
```

故 `before` 已含步进后的值 → `a1 <= a0` → **2070/2441 code 误判「无步进」**，
探针从应得 ~700 掉到 116。修复：分割点取 `ex_ms` 本身。

### 缺陷 ②：bar 时刻过滤一表通吃（已修）

初版对四表统一用分钟收盘时刻 `ms%86400000 ∈ [06:59,07:01 UTC]` 过滤，实测各表约定不同：

| 表 | bar 时刻 | `ms % 86400000` |
|---|---|---|
| `stock_minutes` / `etf_minutes` | 15:00 CST | ∈ [25140000, 25260000] |
| `stock_daily` / `etf_daily` | **00:00 CST** | == 57600000 |

→ 三张日线/ETF 表 **0 探针**（静默失效）。修复：按表选用时刻过滤。

### 缺陷 ③：探针取「窗口内最后两日」而非「除权日 vs 其前一交易日」（已修）

严格探针还必须**按 CST 自然日对齐**：日线 bar 戳 00:00 CST、分钟收盘 bar 戳 15:00 CST，
二者 UTC 日桶不同（00:00 CST = 前一日 16:00 UTC）→ 必须 `(t+8h)//86400000` 归一。

修正前 `stock_daily` 被误判 **51.0% qfq**；修正后：

| 表 | 探针数 | `median(|r-1|/gap)` | 判读 |
|---|---|---|---|
| `stock_daily` | 215 | **0.999** | `r = 1/k` → **raw** ✓ 符合矩阵 |

修正后 `stock_daily` **不再产生任何 CaliberDrift 问题**（假阳性消除）。

### 缺陷 ④：`gap ≥ 2%` 阈值使 ETF 表结构性不可探（已如实分类）

`etf_dividend` 全量 80 条实测**最大除权步进仅 1.925%** → 2% 阈值下 **0 探针**。
降到 0.5% 也只有 23 探针且票型三分（10 raw / 5 double / 8 qfq），无统计意义。

处置：新增 `CaliberDriftNotProbeable`（与「样本不足」区分），
如实说明「本方法对 ETF 表结构性不可探 → 口径由 §5.2 结果导向一致率兜底」，
避免「样本不足」长期误导运维。

## 3. 修复后实测结果：**门禁指标无法区分「云端口径漂移」与「本地缺陷未修」**

### 3.1 严格探针（除权日 bar vs 其前一交易日 bar，gap ≥ 10%）

| 表 | 探针数 | `median(|r-1|/gap)` | `median(r)` | 判读 |
|---|---|---|---|---|
| `stock_daily` | 215 | **0.999** | 0.7224 | `r = 1/k` → **raw** ✓ 符合矩阵 |
| `stock_minutes` | 130 | **0.186** | 1.0014 | `r ≈ 1` → **qfq 样** ✗ 与矩阵矛盾 |

### 3.2 直接比对（同一 code、同一除权日）

```
003018 ex=07-15 k=1.2022   min_close=66.130  daily_close=52.000  m/d=1.2717
603811 ex=06-26 k=1.4401   min_close=15.740  daily_close=7.590   m/d=2.0738
001230 ex=06-17 k=1.4203   min_close=38.450  daily_close=18.830  m/d=2.0420
603881 ex=06-23 k=1.2011   min_close=40.090  daily_close=26.710  m/d=1.5009
300812 ex=06-04 k=1.4021   min_close=51.920  daily_close=26.470  m/d=1.9615
688336 ex=06-18 k=1.4616   min_close=82.190  daily_close=40.150  m/d=2.0471
```

`m/d` 随 `k` 增大 —— 即 `stock_minutes.close` 被 `adj_latest/adj_i` **放大**了。
**这正是缺陷1（未修复污染）的签名**：云端 raw 值被旧公式误乘因子 → 膨胀向 qfq。

### 3.3 全量配对（1,561,348 个 `(code, CST日)` 配对，`stock_minutes` 收盘 bar vs 同日 `stock_daily.close`）

```
pairs  = 1,561,348
exact  =   801,582  (51.34%)   ← 逐位相等
≤0.5%  = 1,272,766  (81.52%)
```

另有 200,000 抽样：`median ratio = 0.99927`，`p95=1.0566  p99=1.1113  max=18.717`。

**median ≈ 1.0 / 51% 逐位相等 + 膨胀长尾** = 「主体为正确 raw + 少数污染单元格」，
即缺陷1 未修复的分布特征，**非云端口径翻转**。

#### 3.3.1 污染单元直证（除权日 `minute.close == daily.close` 逐位相等）

```
002948 gap=0.032  min=5.370  daily=5.37  min/daily=1.0
603811 gap=0.306  min=7.590  daily=7.59  min/daily=1.0
600021 gap=0.023  min=15.040 daily=15.04 min/daily=1.0
```

即分钟表与日线表在除权日**取值完全相同** → 两者同口径（均为 raw）。
先前被计为 `double`（234 票）的探针即由此产生：并非双重复权，
而是**其对比基日落在步进另一侧**导致的假分类。

## 4. 结论（关键设计判定）

1. **§5.3 门禁按原设计（基于本地表口径探测）不可行**：
   本地 `stock_minutes` 的「qfq 样」信号来自**已诊断、待修复的缺陷1 污染**，
   与「云端改返 qfq」不可区分。该门禁会**在修复前后均常亮阻断**，
   属误报，违背「纯增益、不引入新问题」。

2. **根因**：A′ 对 `stock_minutes` **不还原**，故本地表 = 云端值 **逐行直写**，
   历史污染与新鲜漂移在本地表叠加，本地探测无法分离二者。

3. **已实施的处置**：
   - `_CALIBER_BLOCK_STOCK_MINUTES = False`（默认）→ `stock_minutes` 翻转**只告警不阻断**，
     并在 detail 中如实标注「污染与漂移本地不可区分，待数据修复验收后启用阻断」；
   - 数据修复验收通过后将该开关置 `True`，恢复 §5.3 阻断语义（届时本地应为纯 raw）。
   - 该处置有测试双向固化（`test_stock_minutes_qfq_flip_is_blocking` /
     `test_stock_minutes_flip_warn_only_when_switch_off`）。

4. **可辨识的正确形态**（待裁定，二选一或并用）：
   - **(甲) 修复后启用**：门禁保留现设计，但**仅在数据修复验收通过后**作为回归哨兵；
     启用前不参与 `report.passed`。
   - **(乙) 改探云端**：门禁直接对**云端取数**做口径判定（不经本地表），
     从而与本地污染解耦——但需评估云端采样的成本与外部依赖（离线不可用）。

5. **本次实测同时确认的正面结论**（A′ 核心正确性）：
   `stock_daily` 严格探针 `|r-1|/gap = 0.999` → 本地 `close` **确为 raw** ✓，
   A′ 对日线表的「还原 raw」按设计生效；`close_front` = qfq 亦自洽
   （除权日 `close == close_front`，为 qfq 锚定最新因子的定义）。

6. **ETF 两表**：本方法**结构性不可探**（最大分红 1.925%），
   已如实分类为 `CaliberDriftNotProbeable`，口径由 §5.2 一致率兜底。

## 5. 附带发现（独立于门禁）

- `stock_daily.close == close_front` 在**近期 bar** 上普遍成立（锚定最新因子），
  这解释了为何 §5.2 的「close 一致率」类验收必须用**历史除权日**而非近期 bar 才有效。
- 缺陷1 影响面按「膨胀倍数 > 阈」判定的严格探针只有 130/683 命中，
  而全量配对显示 16.2% 单元格偏离 >0.5% —— **污染比例远高于按除权日探针的估计**，
  建议数据修复验收以 §3.3 的全量配对法作为主判据。
