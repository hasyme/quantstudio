## 1. 问题定义

### 1.1 核心发现

**原口径矩阵误判两张日线表为 qfq**（`etf_minutes` 判定正确）：

| 表 | 原矩阵 | 复核结论 | 判定证据（独立基准） |
|---|---|---|---|
| `stock_daily` | 恒 qfq | **RAW** ⚠️ 误判 | raw 误差 **0.0081** vs qfq 0.9963（10,351 配对；adj>1.5 组 6,988 样本 ratio 中位 0.9949） |
| `etf_daily` | 恒 qfq | **RAW** ⚠️ 误判 | raw 误差 **0.0005** vs qfq 0.9350（2,789 配对，差 1870 倍） |
| `etf_minutes` | 恒 qfq | **QFQ** ✅ 原判定正确 | **P5 分层复核**：>10% 幅度组（26 样本）raw 误差 0.5577 vs qfq 0.0485（**差 11.5 倍**） |
| `stock_minutes` | 恒 raw | **RAW** ✅ 原判定正确 | 原 107/107 + 本轮云端基准实测（99.9% 一致） |

> **⚠ P5 纠正记录**：`etf_minutes` 曾被本方案初版（33 样本）误判为 RAW，
> 经 P5 扩样（57,583 样本）+ 幅度分层复核**推翻**，确认 **QFQ**。
> 详见 `docs/evidence/etf-minutes-caliber-correction-20260930.md`。
> **该纠正避免了"把正确的表改错"**。

### 1.2 误判原因（循环论证）

原矩阵判定日线表口径时以「**日线自身**」为参照（`close × ratio` 对日线 raw 偏差
vs `close` 对日线 raw 偏差）——**用待判定的表判断自己的口径**。

> 该缺陷**已在 `stock_minutes` 判定中被发现并修正**
> （原文档 §5.4：「实为**日线参照本身差异**导致的判定失败」），
> 但**日线表自身的判定未同步修正**。

### 1.3 后果

```
误判两张日线表（stock_daily / etf_daily）为 qfq
  → A′ 将两张日线表列入 _QFQ_CALIBER_TABLES（mcp_adapter.py:301）
  → _restore_to_raw 对其无条件施加 × adj_latest/adj_i
  → 云端 raw 被放大
  → 本地 stock_daily 6.4% 行偏高（最高 1.94 倍）
  → 本地日线成为错误"基准表" → A3 判据失效
  → 误判"缺陷1 修复无效"（实为有效，云端基准实测 99.9% 正确）
```

> **C-2 修订（2026-09-30，依审计）**：本图原写「误判**三**表」，
> 与 P5 翻案后的结论（`etf_minutes` 判定**正确**）冲突，已更正为**两张日线表**。

### 1.4 与 A′ 的关系（重要界定）

| 项 | 判定 |
|---|---|
| A′ **核心判断**（`stock_minutes` 不还原） | ✅ **正确**——确实修复了缺陷1 |
| A′ 对 `etf_minutes` 的还原 | ✅ **正确**（P5 确认云端为 qfq）——**保持不变** |
| A′ **错误** | ❌ 沿用原矩阵对**两张日线表**的判定，未独立复核 |
