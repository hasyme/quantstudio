## 2. 严重项（1 项，补完即放行）

### R-1 【严重】B2 残留：§3.1.3 分片收缩会**绕过白名单**下推时间窗口

- **位置**：§3.1.3（L101-106）与 §3.1.2（L96-100）、§3.4（L175）冲突
- **冲突链**：
  1. §3.1.2 / §3.4 规定：表**不在** `passthrough_export_window_tables` 名单 ⇒ **不传** `time_start/time_end`；§3.4 明示「未列名单一律不下推（**仅 async + 分片**）」；
  2. 但 §3.1.3 的分片收缩（`suggested_shards` 消费 / 父窗二分）**子窗必然携带 `time_start/time_end`** 调用 `export_dataset` —— 这本身就是窗口下推；
  3. 因此非名单表一旦触发 `MCPExportBudgetError`，就会在**无任何探针证据**的情况下被下推时间子窗，正是复审 B2 要封堵的场景（passthrough 为 `CREATE OR REPLACE`，`daemon.py:988-991`）；
  4. 另：**「父窗」在非名单表下未定义**——该表并未下推窗口，`_fetch_export_passthrough(table, freq, start, end)` 的 `start/end` 是否为二分父窗未写明，实现者无从判定。
- **修改建议**（二选一，写入 §3.1.3 与 §3.4，各一行即可）：
  - **A（推荐）**：分片收缩视为窗口下推的一种形式，**同样要求表在白名单内**；非名单表发生 `MCPExportBudgetError` 时**不消费 `suggested_shards`、不做二分，直接上抛**（与 M-4「修复前必失败」的判定一致）；
  - **B**：非名单表仅允许消费**服务端 `suggested_shards`**，且必须校验「并集覆盖**全表**」（非覆盖 `[start,end]`）并在 meta 留痕；禁止本地二分自行造窗。
  - 无论选哪种，需同步：① §3.1.3 明确「父窗」定义（名单内 = `[start, end]` 半开；非名单 = 无父窗）；② §5.1 增加「非名单表 + budget error → 不下推子窗」用例。
